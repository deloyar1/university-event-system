# Database Design (Firestore Collections) ## users - id (doc id) - email - password (hashed via Firebase Auth) - role: student | organizer | admin ## students - id - userId (ref: users) - name - profile: { bio, avatarUrl } - interests: [category1, category2] ## organizers - id - userId (ref: users) - orgName ## events - id - organizerId (ref: organizers) - title - description - date - location - classificationId (ref: classifications) - seatLimit - seatsFilled ## classifications - id - name (e.g. Tech, Cultural, Sports) ## registrations - id - studentId (ref: students) - eventId (ref: events) - status: pending | confirmed | cancelled - registeredAt ## bookmarks - id - studentId (ref: students) - eventId (ref: events) ## notifications - id - studentId (ref: students) - message - read: boolean - createdAt ## recommendations - id - studentId (ref: students) - eventId (ref: events) - matchScore (float, 0-1) ## Notes - Firestore is NoSQL, so relations are stored as reference IDs (not foreign keys) - Frequently-read data (like interests) is embedded inside the student document to reduce reads - Separate collections used where data grows independently (events, registrations)
